# 4주 실습 가이드

웹 개발은 운영자가 준비합니다. 모델은 아직 미정이며 실제 AI 실습 전에 도구 호출·언어·비용을 비교해 선택합니다.
첫 2주는 같은 예제, 3주부터 백엔드·데이터 팀으로 나눕니다. 매주 2시간과 조건 3개 비교 과제를 진행합니다.

## 매주 같은 진행 방법

설명·시연 20분 → 두 명씩 구현 60분 → 실패 실험 25분 → 결과 설명 15분.
개발 경험자와 비개발자가 짝을 이루고 실행자·관찰자 역할을 교대합니다.

## 1주: 조건과 역할

현재 프로젝트를 실행하고 데모 표시를 확인합니다.
개발자는 선택한 모델에 단순 질문을 보내는 어댑터를 연결합니다. 처음에는 도구 없이 답변만 받습니다.
비개발자는 같은 조건을 기본 역할/매칭 역할로 비교하고, 어떤 설명이 확인 가능한지 기록합니다.
완료 기준: 모델에 전달하는 조건과 담당 규칙을 설명할 수 있습니다.

## 2주: 준비된 공고

collect.py를 실행해 채용 사이트 목록과 pending을 비교합니다. 실패하면 기본 예제 공고로 계속합니다.
searchSources를 AI 없이 실행해 기술 키워드와 검색 결과를 확인합니다.
코드가 매번 검색한 공고를 모델에 전달하는 매칭 챗봇을 만듭니다.
완료 기준: 공고가 없는 답변과 공고가 있는 답변을 비교하고 출처를 검증합니다.

## 3주: 행동을 선택하는 모델

모델에 search_sources와 read_source를 제공하고 함수 호출 요청을 runAgent에 연결합니다.
모델→도구 요청→서버 실행→모델에 결과 전달→매칭 설명 흐름을 설명합니다.
팀별로 어떤 정보(직무·기술)가 부족할 때 되물어야 하는지 규칙을 작성합니다.
완료 기준: 검색이 필요한 조건과 되물어야 하는 조건에서 동작을 관찰합니다.

## 4주: 실패 원인

상대 팀의 조건으로 테스트합니다. 공고 부족 / 검색 실패 / 설명 오류 / 맥락 오류를 구분합니다.
최소 3개 실패를 수정하고 동일한 조건의 결과를 비교합니다.
완료 기준: 정상 검색·추가 질문·근거 부족 각 한 사례를 시연하고 왜 그렇게 동작했는지 설명합니다.

## 확장 과제 (선택)

- 매칭 점수 계산: 이력서와 공고 요건의 유사도를 산출(RAG/임베딩)합니다.
- 리포트·알림: 매칭 기준 통과 공고를 슬랙·이메일로 보냅니다.
- 자소서 초안: 공고 JD와 이력서를 결합한 맞춤 초안을 생성합니다.

## 쉬운 용어

- API: 프로그램끼리 요청과 결과를 주고받는 연결 방식.
- 스크래핑: 웹페이지에서 필요한 내용을 가져오는 작업.
- 도구: AI가 실행을 요청할 수 있도록 만든 함수.
- 실행 루프: 요청을 실행하고 결과를 돌려주는 과정을 반복하는 코드.
- 어댑터: 서로 다른 모델의 요청 형식을 공통 형식과 연결하는 코드.
- RAG: 관련 자료를 검색해 모델 답변의 근거로 제공하는 방식.
