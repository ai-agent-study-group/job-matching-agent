# Resume Match Agent

이력서와 채용공고를 매칭하는 에이전트 스터디의 기반입니다.
반복되는 구직 작업(공고 확인·요건 비교)을 에이전트가 돕는 흐름을 배웁니다.
웹은 준비되어 있고, 참가자는 공고 검색·읽기와 에이전트 동작, 이력서 매칭을 배웁니다.

**현재는 실제 AI 모델이 없는 규칙 기반 데모입니다.** API 키나 인터넷 수집 없이 실행할 수 있습니다.
실제 모델을 연결하면 모델이 검색 도구와 다음 행동을 선택하고, 이력서와 공고의 매칭 점수를 계산하도록 발전시킵니다.

> germany-life-agent의 UI·구조·문서 구성을 재사용해 이력서 매칭 도메인으로 교체한 스터디 스캐폴드입니다.

## 에이전트 설계 (3단계 파이프라인)

```
[1. 수집 에이전트] ──> [2. 매칭·평가 에이전트] ──> [3. 리포트·액션 에이전트]
 (채용 페이지/메일)      (공고 검색·읽기 + 이력서 비교)   (매칭 리포트/자소서 초안)
```

- 수집: Python 스크립트로 채용 공고를 검토 대기 파일로 수집하고 사람이 승인합니다.
- 매칭·평가: 검색·읽기 도구로 공고를 찾아 요건과 이력서를 비교합니다. (현재 규칙 기반 데모)
- 리포트·액션: 매칭 결과와 출처를 반환합니다. 알림·자소서 초안은 확장 과제입니다.

## 실행

Node.js 20.9 이상, npm을 사용합니다. 프로젝트 폴더에서:

```bash
npm install
npm run dev
```

터미널에 표시된 주소(기본 http://localhost:3000)를 엽니다.
다른 앱이 3000번 포트를 사용하면 `npm run dev -- --port 3001`로 실행합니다.

- `/`: 소개와 직무 분야 선택
- `/backend`: 백엔드·서버 매칭 데모
- `/data`: 데이터·AI 매칭 데모
- `/admin`: 스터디원용 구현·학습 안내. 주소로 직접 접근하며 공개 메뉴에는 표시하지 않습니다.
- `/study`: 기존 주소를 `/admin`으로 이동합니다.

`.env.example`은 설정 이름의 예시입니다. 현재 데모에서는 `.env.local`을 만들 필요가 없습니다.

## 화면 뒤에서 일어나는 일

```text
공고 준비: 채용 사이트 → Python 수집 → 검토 대기 파일 → 사람이 승인 → 앱 공고
매칭 응답: 채팅 → 서버 → 검색 도구 → 읽기 도구 → 매칭 설명과 출처
```

현재 데모는 검색→첫 결과 읽기→준비된 요건 표시 순서로 움직입니다.
데이터 페이지에서 직무·기술 없이 "추천"을 요청하면 어떤 직무·기술 기준인지 되묻습니다.
연봉을 물으면 요약에 연봉 정보가 없다고 보류합니다.
도구 기록은 실제 실행 결과이며, AI의 생각이나 실시간 진행 상황을 가장한 기록이 아닙니다.

예시 공고 4건은 매칭 흐름을 설명하기 위한 사람 작성 요약입니다. 실제 채용 공고가 아니며 합격·연봉을 판단하지 않습니다.
[공고 관리](docs/DATA.md)에서 수집 대상과 갱신 방법을 확인하세요.

## Python 공고 수집

Python 3.10 이상을 권장합니다. Node.js 앱과 별도로 실행합니다.

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r scripts/scrape/requirements.txt
python3 scripts/scrape/collect.py
```

Windows PowerShell에서는 활성화 명령 대신 `.venv\Scripts\Activate.ps1`을 사용합니다.
수집할 URL과 본문 위치는 `scripts/scrape/sources.json`에서 지정합니다.
스크립트는 `data/pending/<공고ID>.json`에만 저장합니다. 실패 시 기존 파일을 유지하고 종료 코드 1을 반환합니다.
자동 링크 탐색이나 정기 수집은 없습니다. 사이트가 바뀌면 본문 위치(selector)를 고쳐야 합니다.

**승인하기 전에 반드시** 원문과 본문을 비교하고, 광고·중복 내용·개인정보를 제거합니다.
기술 검색어를 확인하고, 데모 답변으로 사용할 경우 본문을 짧은 한국어 요약으로 편집해 `language`도 수정합니다.
그다음 검토한 공고 한 건만 승인합니다.

```bash
python3 scripts/scrape/review.py --approve wwr-backend
```

승인은 같은 ID의 앱 공고를 교체하므로 파일 변경 내용을 확인하세요.
앱은 `reviewed: true`인 공고만 읽습니다. 수집을 하지 않아도 동봉된 예제로 동작합니다.

### 수집 호스트와 차단

허용 호스트는 `weworkremotely.com`(공개 공고 목록)과 `www.linkedin.com`입니다.
링크드인 등 대부분의 채용 플랫폼은 자동 수집을 차단하거나 약관으로 금지하며 **공식 API 사용을 권장**합니다. 우회하지 않습니다.
차단 동작을 관찰하려면:

```bash
python3 scripts/scrape/collect.py --manifest scripts/scrape/linkedin-example.json
```

[저장 파일 예시와 상세 검토 방법](docs/DATA.md) · 웹에서는 `/admin#collection-examples`에서 확인할 수 있습니다.

## 실습 안내

비개발자: 예시 조건 실행 → 활동 기록 확인 → 공고 비교 → 필요한 조건/검색어 작성.
개발 경험자: 각 주차의 함수 수정 → 같은 조건 다시 실행 → 결과 비교.

1. **AI 연결:** `lib/providers/types.ts`를 보고 선택한 모델의 어댑터를 작성합니다.
2. **공고 검색:** `lib/tools/sources.ts`에서 기술 키워드와 검색 결과를 개선합니다.
3. **에이전트:** `lib/agents/run.ts`에서 모델의 요청→실행→결과 전달을 관찰합니다.
4. **평가:** `docs/EVALUATION.md`의 조건으로 두 팀이 서로 테스트합니다.

[4주 실습 안내](docs/STUDY.md) · [설계](docs/ARCHITECTURE.md) · [디자인](docs/DESIGN.md)

## 실제 AI를 연결할 위치

`ModelProvider.decide()`는 현재 조건, 담당 규칙, 도구 정의, 이전 도구 실행 결과를 받고
`answer` 또는 `tool_call`을 반환합니다. `lib/providers/demo.ts`가 현재 구현입니다.
실제 제공자의 어댑터는 검색 결과를 각 API의 도구 결과 메시지로 변환해야 합니다.
`callId`로 모델 요청과 결과를 연결하고 모델 호출에 시간 제한을 설정합니다.
매칭 점수 계산과 이력서 벡터화(RAG)는 이 단계에서 붙입니다.

현재 `AGENT_PROVIDER=demo`만 지원합니다. 다른 값을 넣으면 요청에 설정 오류가 반환됩니다.
데모는 프롬프트를 이해하는 모델이 아니므로 역할 규칙을 고쳐도 데모 답변은 바뀌지 않습니다.
데모 동작을 고치려면 `demo.ts`를 수정하고, 프롬프트 효과를 보려면 실제 모델을 연결하세요.
