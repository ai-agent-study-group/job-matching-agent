# 이력서와 공고 데이터 논의

Phase 1의 입력은 이력서 파일과 채용공고 JD입니다. 아래는 설계 질문이며 세부 형식·수집 범위는 미정입니다.

## 이력서 입력

| 항목 | 논의할 것 | 결정 |
| --- | --- | --- |
| 파일 형식 | PDF·Word 중 우선 지원 형식, 스캔 문서·OCR 포함 여부 | ? |
| 크기·개수 | 파일 크기·개수 제한과 처리 실패 안내 | ? |
| 추출 항목 | 경력·기술·학력·언어 등 비교에 필요한 정보 | ? |
| 추출 확인 | 잘못 읽거나 빠진 정보를 사용자가 확인·수정하는 흐름 | ? |
| 보관·삭제 | 원본·추출 정보의 저장 위치·기간·삭제 방법 | ? |
| 평가 자료 | 공개 가능한 가상 이력서·공고 쌍의 작성·관리 | ? |

공개 문서·평가 예시에 실제 이력서 원본이나 개인 연락처를 넣지 않습니다.

## JD 수집과 정규화

| 항목 | 논의할 것 | 결정 |
| --- | --- | --- |
| 우선 사이트 | Phase 1 첫 사이트와 공고 범위 | ? |
| 수집 경로 | 사이트가 제공하는 API·피드·페이지 및 접근 조건 | ? |
| 실행 주기 | 백그라운드 수집 주기와 “최신”의 기준 | ? |
| 고유 ID·중복 | 원문 URL, 공고 ID, 동일 공고·수정 공고 구분 | ? |
| 추출 항목 | 필수 요건·우대 사항·주요 업무, 출처와 수집 시점 | ? |
| 마감·변경 | 마감·삭제·수정 공고를 목록에 반영하는 방법 | ? |
| 실패 처리 | 수집 실패·누락·본문 오류의 기록과 재시도 | ? |

기존 `src/scraper/README.md`의 ATS 예시는 후보 자료이며 회의에서 우선 사이트를 확정한 것은 아닙니다.
기존 `web/`의 수집 예제·예시 공고도 운영 데이터 수집 완료를 뜻하지 않습니다.
