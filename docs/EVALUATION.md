# 매칭 평가와 완료 기준 논의

정확한 산식·사례 수·통과 기준은 아직 미정입니다. 아래는 다음 회의에서 고를 평가 관점입니다.

## 확인할 사용자 흐름

| 영역 | 확인할 질문 |
| --- | --- |
| 업로드 | 지원 파일을 읽고 미지원·손상 파일에는 이해 가능한 오류를 보이는가? |
| 이력 추출 | 경력·기술이 원문과 일치하며 누락·추정한 정보를 구분하는가? |
| JD 분석 | 필수·우대·업무 내용을 구분하고 원문 근거를 확인할 수 있는가? |
| 요건별 비교 | 충족·부족·정보 없음을 혼동하지 않고 이력에 없는 역량을 만들지 않는가? |
| 점수 | 같은 기준으로 계산하며 어떤 요소가 점수에 영향을 줬는지 설명할 수 있는가? |
| 추천 | 합의한 선별·정렬 기준에 맞고, 공고 원문과 수집 시점을 확인할 수 있는가? |
| 오류·운영 | 수집 실패·모델 오류·시간 초과·결과 없음에서 사용자가 다음 행동을 알 수 있는가? |

회의의 “매칭 확률(%)”는 실제 합격 확률로 검증된 값이 아닙니다.
점수의 이름·설명·산식·가중치·정보 부족 처리와 평가 방법을 먼저 합의해야 합니다.

## 사례와 결과 기록 후보

`사례 ID / 가상 이력서 / JD·출처 / 기대 요건 비교 / 실제 결과·점수 / 근거 / 실패 유형 / 실행 설정 / 개선 메모`

평가셋 개수·라벨 기준·평가 역할·시연 통과 조건: ?
기존 `eval/README.md`의 약 30개 공고는 기존 계획의 예시이며 이번 회의에서 확정된 개수가 아닙니다.

- 매칭 근거·정보 부족·오류를 어떤 방식으로 검토할까? ?
